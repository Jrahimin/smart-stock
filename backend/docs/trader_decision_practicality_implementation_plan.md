# Practical, coherent trader decisions — integrated implementation plan

Status: **refined final plan; planning only**. Investigated and revised 14 November 2026 against `main`, **1fc28f9** (PR #31). No application code, policy, database contents or deployment changed in this investigation. Live measurements below are from the preceding read-only audit; this revision rechecked the relevant code, not a new live session.

## Outcome and scope

One cohesive backend-to-frontend implementation, followed by **one independent end-to-end review and one consolidated repair session**. Keep the current design, contracts, immutable publications, shared decision engine, quote assessment, capture/replay and query lifecycle. No new model, buy quota, trading feature or broad redesign.

The trader journey must answer, in order: **why watch it → can a new buyer use this plan → what blocks or weakens it → what would change that → what should an existing holder review?** Attention, setup quality, entry permission, quote applicability and holder guidance remain distinct. Zero Potential Buys is an acceptable result.

Correctness, contextual interpretation and clarity fixes can ship after regression/replay checks and chart review. Selectivity changes get a **20-session, predeclared operational shadow review**, not a six-month prerequisite. The existing 120-session research experiment remains separate and unchanged. All changed rules remain versioned; operational acceptance is not proof of superior returns.

**Review adjustments:** adopt all seven requests, with two qualifications. Persistence that changes which entries are permitted is a selectivity change, even if the old rule was crude. Also, nearby resistance may explain many failed plans, but breakouts already use projected targets: measure the causes before changing target selection. The longer research gate is not currently a precondition in the live engine; absence of such a gate is not evidence that the current rules are validated.
