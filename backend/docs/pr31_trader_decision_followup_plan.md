### Commit A — establish which price was compared

Keep one backend evaluator. Price basis describes evidence; plan eligibility still depends on identity, data quality, post-publication history, invalidation, expiry, entry zone and required completed-session confirmation.

| Evidence | Assessment and expiry |

- **Revised calendar policy.** Obtain the closing session identity from finalized publication and its matching valid traded row. Use exchange time for market boundaries. Across a known closure, carry the latest completed session with its actual date. If the feed is silent on a scheduled trading day and neither closure nor publication health is established, show the last close as dated context and withhold current eligibility. During scheduled open hours never extend yesterday’s eligible close merely because today's feed is silent. Do not turn missing data into a holiday or silently substitute yesterday's close during finalization.
- **Revised receipt safeguards.** Identical OHLCV can acquire a new receipt (`market_data_repository.py:541`). Require the current instrument, trading session, eligible quality, positive price and evidence of trading in that session. Reject NO_TRADE, zero volume, mismatched dates, future receipts and invalid supplied source times. Positive cumulative volume proves some trading that day; it cannot establish a recent trade. Describe the time as retrieval time. A refresh of the page, cache or DB row cannot renew it. A provisional observation cannot confirm a breakout.
- **Revised trigger and rollout.** In both backend Pulse projections and the browser, require APPLICABLE **and explicitly CURRENT** for an actionable trigger, after existing evidence checks. Default missing and unknown bases to no trigger. Use client capability opt-in for the new contract: legacy requests keep the existing response semantics, while Phase 2 opts in for SNAPSHOT, receipt-based deadlines and timestamp-free finalized closes. Partition server, SSR, query and IndexedDB cache identities wherever the contract can differ. Keep the new path off for general clients until compatibility tests pass. Retain MARKET_CLOSED as a readable legacy code; use SESSION_SETTLING only for the actual publication gap.
- **Revised fact projection.** Reuse structured facts from the same stock and decision generation. Supply nullable RSI, trend, opportunity score, relevant trigger/resistance, and volume versus the **prior 20-session median**, using the existing Pulse baseline (`market_pulse_briefing.py:457`). Omit the ratio if that baseline is unavailable. This is a display contract; preserve the baseline used by each existing strategy rule.
- **Revised operational proof.** Emit one daily aggregate per exchange and session from existing operational logging. Count distinct assessed instruments per CURRENT, SNAPSHOT, LAST_CLOSE and UNVERIFIED, with UNVERIFIED counted by status first. Deduplicate repeat reads and log the population, assessment time and top unavailable reasons. Use a defined open-session and post-finalization observation in the daily summary so the closing pass does not erase evidence of intraday use.

- Preserve exact-fraction handling at classification boundaries. Defer a Decimal rewrite, arbitrary coverage percentage and a change to heatmap weighting.
- Measure payload size and journal-query time before server pagination, a new slim endpoint or path caching. Never cache final eligibility solely by generation because time can expire within it.
- Defer a Portfolio rewrite, Login redesign and historical strategy changes. Fix a holder discrepancy only if parity testing reproduces one. Keep the earlier corrected market, theme and publication behavior covered by regression tests.
