# Trader practicality offline evidence contract

The audit CLI reads local JSON only and calls the central decision, quote, publication, path, Scanner and Pulse owners. It does not query or mutate a database, contact a provider, activate a candidate or record research receipts. Each output binds source input hashes, source code hashes, original generation, context/calendar/evidence, output digest and a distinct counterfactual generation. Changing a context row, quote journal or policy produces a different derived identity.

## Capture and source records

`captures` contains complete immutable publication envelopes: `generation_id`, `exchange`, `session_date`, aware `observed_at`, `invalidated_at`, `input_payload` and `result_payload`. Inputs/results must reconcile against `universe_membership`, `excluded_members` and `membership_provenance.status=OBSERVED_INDEPENDENT_LISTED_SET`. Owning canonical input hashes and immutable row digest are verified. Metadata-only exports are excluded; a selected accepted subset is explicitly labelled and has no whole-universe denominator. The original nonwithdrawn complete vintage is selected per session; corrections require explicit `--publication-id` selection.

Production capture preserves raw `input_payload.market_context` with `context_session_date`, `generation_id`, `source_revision` (committed value payload hash), capture `known_at` and authenticated input availability only when the row was a valid finalized, then-known input. The shared producer revision payload contains session/index, close, advancing/declining, source, finality and database revision clock; `unchanged` participates only when present, distinguishing the earlier omitted format from explicit null. Strict C1 and strict two-session C2 validate the complete producer collection's selector/value shapes and recompute every claimed digest before index routing, date ordering, window cropping or tied-candidate selection, including C1's51st phase dependency. A malformed or altered observation invalidates that context vintage; it cannot disappear into a filter and permit older-row backfill. Producer dates must be canonical ISO dates, knowledge clocks must be aware, and malformed JSON selector/metadata values fail closed. Equal-known-time candidates compare the complete committed payload, including optional `unchanged`; conflicting valid revisions are UNKNOWN in either input order. Nonfinite/unhashable sidecars are excluded as `INVALID_MARKET_CONTEXT_VALUES`, supplying no canonical context digest or market authority; the original export byte hash remains provenance. The consuming boolean validator fails closed while the producer retains its existing strict hash behavior. Existing clocks/ownership/calendar checks remain independent, including committed database revision at/before the claimed knowledge clock. This proves availability at that capture; it does not attest an earlier historical vintage or execution quote. Audit resolves owning context and earlier captured vintages, rather than replacing old inputs with a later top-level summary. Original summaries without this provenance remain reconstructed only: their table identity is `source_record_id`, never a producer `source_revision`. Presence of a producer revision always claims captured evidence, even if mutable authentication/provenance flags are removed or false, and reconstruction cannot bypass its validation.

Strict derived C1 checks generation/knowledge/authentication facts, including a supplied database revision clock, before accepting finality. Every emitted regime fact depends on the last fifty-one then-known final index observations, including the preceding observation used by the phase comparison. Without that complete provenance it emits a stable neutral/zero-confidence/UNKNOWN regime. Later export summaries cannot change strict canonical facts or identities. A hash-verified supported immutable owning-v4/schema-v4 C1 input always retains its captured regime in C1 and dependent correction arms in both strict and reconstructed modes. A mode flag, empty export or lossy sidecar supplies no new evidence and cannot upgrade a known owning rejection. This preserves prior producer formats that omitted optional breadth fields; it is owning restoration, not reconstruction. Non-owning v2/v3-to-C1 comparisons require raw evidence in strict mode and may explicitly use separately labelled retrospective reconstruction. Distinct market-policy candidates remain deliberate counterfactual rules, never owning publication replacements. Capture preserves optional `unchanged` breadth: zero and explicit null retain live semantics, while a negative count remains invalid. An old omitted key cannot prove a null value or upgrade an immutable owner.

Both supported captured producer formats explicitly supply `generation_id`, `context_session_date`, `authenticated` and `provenance_status`. Missing ownership is never inherited from the enclosing publication. Positive authentication must agree with `CAPTURED_AS_KNOWN_COMPLETED_INPUT`; false authentication must agree with `UNVERIFIED_INPUT`. C1 and C2 share per-session selection: group the validated collection by session, select the latest then-known instant, compare all tied committed facts before checking trust, and retain unresolved dates in place. C1 then crops fifty-one distinct dates, not physical rows. Identical duplicates are harmless; a genuinely later valid correction can win before the cutoff; a conflicting boundary or untrusted winning observation cannot disappear and invite older backfill. Valid provisional history outside the required window grants no authority and does not invalidate otherwise complete required sessions.

Production C1 construction, capture/restore, strict audit and reconstructed replay compare required summary dates with the known `exchange_session_dates` when supplied. A known interior missing summary therefore leaves completeness false instead of borrowing an older close. This is a negative gap check, not an attestation that those observed dates form a complete calendar. The normal repository query derives dates from finalized DSEX rows and cannot independently detect a whole day missing from that same table. No weekday calendar is invented; independent calendar absence still blocks strict C2, and immutable historical owners remain unchanged.

Owning v2/v3 lineage uses input schema v3 and excludes the additive regime metadata from its hash. Current v4/candidates use schema v4 and round-trip `as_of_session`/`required_inputs_complete`. Current C1 requires the actual as-of index, fifty-one finite observations, valid breadth and explicit `is_finalized=true` on every required index observation. Missing/provisional finality is UNKNOWN; only the separately labelled reconstructed diagnostic may use it. Raw finality is preserved in captured market context and its revision hash. Strict C2 also requires complete independently authenticated exchange history and the exact selection-time vintage for both consecutive sessions and their fifty-session windows.

Prior context and its publication cutoff are selected together by the owning-vintage selector, ordered by aware observation clock/date/ID. Input order cannot select a correction. `--publication-id` explicitly selects a nonwithdrawn correction; a withdrawn/ambiguous explicit selection fails closed. Context from a different generation is rejected. Observed holidays require the independent calendar rather than weekday inference.

## Independent market calendar

`input_payload.market_calendar`, or `market_calendars_by_generation[generation_id]`, must contain:

```json
{
  "status": "VERIFIED_EXCHANGE_SESSION_CALENDAR",
  "complete": true,
  "source_revision": "an independently authenticated exchange-calendar revision",
  "known_at": "2026-11-12T10:00:00+00:00",
  "range_start": "2026-08-01",
  "range_end": "2026-11-12",
  "sessions": ["dates supplied by that source"]
}
```

Calendar sources are validated explicitly rather than chosen by dictionary truthiness. Production's nonempty `complete=false` unavailable placeholder cannot mask a verified supplement. A supplement must also carry the exact owning `generation_id`; an embedded calendar is scoped by its immutable capture. Both need a nonempty revision, canonical distinct session dates, a complete required range and aware knowledge at/before the owning observation cutoff. Invalid/future claimed verification and conflicting required session histories fail closed. Agreeing verified sources may retain the captured source; neither an unverified marker nor a later receipt supplies historical authority.

Neither verified source may omit a positively known trading date inside its actual required fifty-one-session interval through the assessment session. This interval comes from the candidate's selected session window, not a declared range that could hide older-row substitution. Contradictions use owning captured `exchange_session_dates`, the production unavailable placeholder's scoped observed dates, and authenticated finalized DSEX observations from the already-selected, generation-bound, then-known vintages. The placeholder supplies negative contradiction evidence only; it never establishes a complete calendar. Foreign, future-to-vintage and unverified observations supply no such evidence. A contradiction emits `CONTRADICTED_BY_KNOWN_SESSION` with the omitted dates and leaves strict C2 UNKNOWN; a changed supplemental revision cannot bypass it. Partial observations need not equal the full calendar, and positively observed older dates outside the required interval do not invalidate it. Missing observations still cannot establish a holiday or independent coverage. C1 and immutable published owners retain their own regime evidence.

The list must cover at least the actual last fifty-one exchange sessions through the as-of date. Missing whole days cannot be inferred to be holidays. `StrategyInput.exchange_session_dates` derived from raw price dates is not independent calendar proof. The current repository does not expose an authenticated complete calendar reader; captures explicitly record `INDEPENDENT_CALENDAR_COVERAGE_UNAVAILABLE`, observed raw dates and `complete=false`. Consequently strict C2/forward readiness remains unknown until this evidence exists. No weekday reconstruction upgrades it. Reconstructed diagnostic mode is labelled separately and cannot satisfy readiness.

## Entry evidence from existing read-only source tables

The adapter consumes the existing export's `quote_prices`, `price_observations`, `price_publication_observations` and `market_generations`, plus `exported_at`. `market_schedule` must contain a source revision and the existing settings fields needed to resolve session boundaries, configured closures/overrides and cadence. A bounded exporter must include `source_coverage` for all four sources, with `complete=true` only when the complete required range was actually read; the price journal also supplies an aware `range_start`. Limits/truncation cannot be relabelled complete. This is an export attestation of query coverage, not permission to manufacture source timestamps or price-publication records.

The adapter reuses production `publication_evidence`: finalized generations need the existing `PRICE_VERSION_MEMBERSHIP_V1` publication observation with exact immutable OHLCV membership, manifest/sync identity and observation time. A finalized-generation row alone is insufficient. It passes original prices/revisions/publications to `build_quote_projection`, `build_entry_price_evidence`, `build_entry_path_facts` and `evaluate_entry_applicability`. Source-proven traded dates and genuine publications authenticate the quote's session; receipt-only data cannot establish a new session. Missing source range, schedule, membership or publication proof fails closed. Known authenticated breaches remain invalid even if later coverage is incomplete or the current quote recovers.

For already captured bound evidence, `input_payload.entry_evidence` or `entry_evidence_by_generation[generation_id]` must bind `decision_generation_id`, `publication_observed_at`, an aware `assessed_at`, `quote_generation_id` and each member's original `input_hash`. It includes original quote/path records, clocks, complete source coverage and exact publication evidence. These are explicit source facts, never manually inferred `authenticated=true` replacements. The table adapter constructs this form prospectively; controlled regression evidence uses the same path with every fabricated source/clock labelled CONTROLLED.

The same read-only export must include `corporate_actions` (`stock_id`, `action_subtype`, `effective_date`) and `dividend_events` (`stock_id`, `status`, `ex_dividend_date`, stock/cash dividend percentages and cash amount). Production and audit share the event projector: SPLIT/BONUS/RIGHTS/MERGER and approved/paid positive ex-dividends change the price basis. Per-table `source_coverage` requires `complete=true`, `source_revision`, stock scope (`stock_ids` or `scope=ALL_STOCKS`), aware `known_at`, and `range_start`/`range_end` spanning reference through assessment. Empty arrays require the same coverage attestation; absence is UNKNOWN. Unknown/future event knowledge cannot prove absence. A genuine earlier stop breach keeps precedence over later basis changes or missing coverage.

Both raw table arrays must be explicitly present, including a covered `[]`; a receipt alone cannot turn an absent/null payload into verified emptiness. Already captured bound evidence has a separate payload contract: its explicit `basis_evidence.events` array and both coverage receipts are validated without requiring the raw export tables again. Missing/null captured events remain unknown. Known authenticated stop-breach precedence is unchanged in either format.

Prospective export recipe: within the existing bounded, read-only repeatable-read export transaction, page both existing source tables for the independently captured stock IDs and reference-to-assessment date range; include relevant null-date records as uncertainty, retain all projector fields and any original revision knowledge, and count/reconcile every page. Record transaction snapshot time as coverage `known_at`, the exact requested stock/range, a digest of rows plus query bounds, and `complete=true` only after the uncapped full range reconciles. This attests the current snapshot (including a genuinely empty table), not earlier point-in-time availability. If individual event knowledge is absent, the adapter uses that snapshot knowledge only for assessments at or after it. Production's existing `MarketDataRepository.list_entry_basis_events` fetches these same tables through the shared projector; no new migration or manual `authenticated=true` field is needed. The November export has neither table/coverage and remains UNKNOWN; it must not be edited to fill the gap.

The Nov13 export has zero price-publication observations, null sampled source/receipt clocks, capped generation/journal history and no complete independent market calendar. It cannot authenticate a positive live close or elapsed twenty-session measurement. Strict output retains UNVERIFIED/UNKNOWN. The executable positive/current/breach regressions are CONTROLLED; they do not change that conclusion.

## Operational report and fixture output

`--shadow-freeze DATE --expected-sessions calendar.json --freeze-manifest freeze.json --human-reviews reviews.json` requests the operational report. The calendar object contains `complete=true`, `source_revision`, aware `known_at`, a complete `range_start`/`range_end` covering the freeze and window, and twenty distinct ordered `{session_date, authenticated=true, next_open_at}` records, with each next-open linking to the next actual exchange session. The freeze document binds a 64-character `source_hash`, `baseline=trading-intelligence-v4`, exact seven arm names, `freeze_date` and aware `recorded_at`.

Human receipts name `operational_owner` and exactly one review for each distinct Sunday-start DSE week represented by those authenticated sessions, including partial/holiday weeks. Each has distinct `review_id`, `week_start`, `reviewer`, matching `signed_by`, `decision=SIGNED_ACCEPT` and aware `reviewed_at` after that week's last observed session. Selected `cases` bind actual `case_hash`, `session_date`, `arm` and `stock_id` from the frozen chart inventory. Exact integer `case_count`, `permitted_count`, `rejected_count` and per-stratum `coverage.available_count/reviewed_count` must reconcile; absent strata need that week's `shortfalls` with stratum and reason. Available strata cannot be left unreviewed. Duplicate/undated receipts fail closed. These are external human receipts, not agent-created completion claims.

Weekly date boundaries use `reviewed_at` converted to Asia/Dhaka. Equivalent UTC and `+06:00` spellings therefore have identical Sunday-start week/date results. Case-knowledge and report-cutoff comparisons continue to use absolute aware instants; local-date normalization cannot admit a receipt before the evidence was known or after the report cutoff.

For each actual weekly inventory, review at least ten permitted and ten rejected cases, or every available case when that population has fewer than ten. A shortage also requires a `shortfalls` item with `population=PERMITTED|REJECTED`, exact integer `available_count`, `reviewed_count`, `target_count=10` and a nonempty reason. These counts bind the dated week's frozen inventory; honest smaller claimed counts alone cannot satisfy a sufficiently populated sample.

Sampling counts distinct stock/date/source/economic-thesis charts. Central guardrails provide `thesis_hash` from decision facts and proposed geometry, excluding policy/strategy/input/shared-ID lineage fields. Unchanged arm copies therefore count once even when their lineage IDs differ; actual decision, permission, confirmation or geometry changes remain distinct. Original arm-specific case records and hashes remain available. Receipts may reference multiple arm copies for inspection, but selected/available counts, strata and shortfalls reconcile to distinct charts, with strata combined across the paired unchanged copies. Missing semantic chart identity cannot supply a validated sample.

Readiness checks elapsed dates, timely complete owning C1 captures, paired membership/hash/output/code identity for C1 and all six candidates, safety/evidence shortfalls, action-change attribution and exercised exceptions. Required market evidence uses effective canonical permission UNKNOWN, including invalid breadth; the diagnostic cannot hide this behind a nullable raw permission. The changed-permission stratum requires a BUY/non-BUY crossing. Rejected AVOID/WAIT changes remain inspectable changed decisions, but do not meet that stratum. Zero-buy sessions count; unexercised exceptions stay in shadow. Missing evidence yields NOT_READY. Even a complete clean window yields only READY_FOR_DAY_20_HUMAN_DECISION, never automatic activation. Named operational role assignment and human weekly chart reviews remain pending in this implementation.

Exception credit is arm-specific: risk and combined each need the actual HIGH-risk exception; pullback and combined each need the actual completed-pullback-hold rule. `CENTRAL_EXCEPTION_ENTRY_PROOF_V1` binds the central policy predicate, permitted candidate input/decision ID, central `APPLICABLE/ENTRY_TERMS_MET` assessment, complete verified path/basis evidence and later completed confirmation where required. One shared predicate produces and validates this conditional exercise proof. Genuine authenticated LAST_CLOSE and bounded, independently session-verified SNAPSHOT assessments can establish dated exercise. Central assessment still owns all quote freshness, publication, invalidation, expiry and confirmation checks; receipts are never relabelled source clocks. Baseline, ordinary-market pullbacks, another arm's flags and pooled booleans provide no credit. `unexercised_exception_arms` lists remaining arm/rule pairs.

Conditional exercise is neither a CURRENT trigger nor a fill. Proof records separately carry `current_trigger` from the unchanged central trigger predicate; guardrails report `current_trigger_exceptions` and readiness reports `current_trigger_exception_arms`. An ordinary permitted thesis with an unverified current quote is reported in `unverified_permitted_quote_observations`, rather than vetoing the whole twenty-session review. Hard safety violations, required market evidence and the exception's own trusted path/basis/assessment requirements remain gates. Missing fills/returns remain unknown, and none of these observations activates C2.

Each date/arm folder contains raw serialized `universe.json`, `signals.json`, `pulse_focus.json`, `pulse_monitor.json`, per-symbol `details/*.json`, `diagnostics.json`, `funnel.json`, `manifest.json`, `paired-evidence.json` and `controlled-transitions.json`. They are raw DTOs; a local QA harness supplies normal HTTP envelopes. Controlled folders additionally contain `freshness.json` and an explicit evidence/clock manifest. Positive LAST_CLOSE stays a dated reference until the next open; client OPEN freshness withdraws it immediately. The separate backend next-open fixture can have a future clock relative to Chrome and is labelled accordingly. No browser virtual-time or real-feed authority claim follows from those controls.

Controlled manifests also preserve `read_time_assessor.contract=CONTROLLED_ENTRY_FACTS_V1`: exact quote/source/receipt/publication facts, the full path/session context, owning decision ID and plan/eligibility hashes. The QA harness re-runs the actual applicability evaluator at request time on those frozen facts. It advances assessment-now and the explicitly declared next-open boundary; it never renews source clocks, invents path observations or patches a positive status. Missing/mismatched context fails closed, the next open with the old close is UNVERIFIED, and history after the bounded controlled window remains unverified. Every read keeps the same frozen fixture generation; identity output exposes the immutable facts hash and actual read-time assessment.

Production and audit Details share the complete delivered summary projection, including evidence status, selected facts and policy/data eligibility reasons.
